# Codex 与 SciencePAL：同一个团队科研项目

2026-10-30。已实现成员身份、冻结协议、任务领取、跨成员评审、返工、R2 与文件交接的统一流程。Codex 使用本地任务包，SciencePAL 使用远端成员连接器；两者产生同一项目中的运行与成果记录。

## 先演练，不需要账号

在 vibe-git 目录，用 Node.js 24+：

```powershell
npm ci
npm run build
npm run sciencepal:simulate -- --mixed
```

此命令只启动临时回环 Host，不使用 Key、真实模型或公网隧道。成员 A 通过真实 CLI 的 bind-codex/next/take/submit 执行本地确定性计算，成员 B 通过真实连接器与模拟 SciencePAL 交接。角色和平台调用均明确标记为模拟。

已验证的过程：Codex 对齐和执行 → SciencePAL 等待输入 → 明确答复并原线程续接 → SciencePAL 退回缺少单位的成果 → Codex 返工 → SciencePAL 批准并计算下游 → Codex 独立复评 → 成员提出 R2 → 队长确认 → 重新执行与交叉评审。

共 13 个逻辑任务运行、1 次原线程续接，R1 和 R2 均验收通过。脚本另保留独立 bridge 的兼容演练；两部分共 20 项检查。126 项科研回归通过。结果在 `data/mixed-team-simulation/simulation-report.json`、`regression.json`、按项目 ID 命名的 R1/R2 证据文件；本地数据不包含在发给队友的源码包内。

## 真实接入

推荐先按 [图形接入说明](SCIENCEPAL-FIRST-RUN.md) 启动本人入口，在原版算力网中选择平台、保存提案与启动连接器。下面的 CLI 仍用于 Codex 任务领取和诊断。

沿用 [队友接入说明](SCIENCEPAL-TEAM-QUICKSTART.md) 的 Host、成员邀请、本人提案和项目创建步骤。**在创建项目之前**选择每人的平台。已冻结项目不因后续重新绑定而改变，需要新的混合项目；不迁移或覆写旧实验。

Codex 成员在自己的 Codex 工作区终端配置原成员身份。队长可以运行下面的环境脚本；普通成员按接入说明先 join：

```powershell
.\scripts\sciencepal-member-env.ps1 -Captain
npm --silent run sciencepal:member -- bind-codex
npm --silent run sciencepal:member -- plan .\fixtures\team-research\captain-proposal.md
npm --silent run sciencepal:member -- doctor
```

Codex 成员不需要 SciencePAL Key，不使用 `-SaveKey`。SciencePAL 成员仍在本人机器上运行 agents/bind/plan/doctor，使用自己的 Key。队长使用 prepare/create 选择两份提案，随后 align、检查对齐稿、publish；这些发布权限没有交给模型或普通成员。

项目建立后，Codex 成员可在原拓扑待办中“准备本人任务包 → 复制给 Codex 的任务说明 → 检查并交回成果”；实际计算和评审由本人 Codex 完成。文件目录按成员、Host、项目、运行隔离；已在 CLI 领取的任务仍使用原目录。以下 CLI 路径继续可用：

```powershell
npm --silent run sciencepal:member -- next PROJECT
npm --silent run sciencepal:member -- take PROJECT 'C:\你的个人目录\research-task-001'
# 让当前 Codex 读取返回的 TASK.md 与 inputs/，完成真实计算或评审
npm --silent run sciencepal:member -- submit PROJECT 'C:\你的个人目录\research-task-001' 'C:\你的个人目录\research-task-001\data.json'
```

示例中的 PROJECT 和目录需替换。输出文件名以 take 返回的 output 为准；对齐、评审和变更评审各自使用其约定文件名。输出是包含 revision/inputReceipts/result 的完整 envelope，格式在 TASK.md 中。必须从 inputs/ 原始字节计算 SHA-256，不能用旧任务的上下文哈希代替本次回执。

网页入口与 take 复用同一套领取、冻结输入和交回校验。take 会返回任务种类、目录、输入和输出路径。该工具不自动启动 Codex 模型：当前 Codex 读任务、使用本地工具、写成果，再调用 submit。可让 Codex 按下面的指令连续处理：

> 使用我已配置的成员身份参与 PROJECT。先 next；本人 Codex 任务用 take 领取到新目录，读取全部冻结输入，完成 TASK.md 后 submit。跟进评审反馈和下一项本人任务。需要队长裁决、明确答复或新增资源授权时停在对应待办；不要替别人批准，不重复提交远端任务。

SciencePAL 成员继续保持 `work PROJECT` 运行。它只领取本人冻结为 SciencePAL 的任务，不会把 Codex 任务发到平台。任务依赖和评审通过后，Host 自动派发下游。

## 现在轮到谁

项目页顶部新增“现在轮到谁”；`next PROJECT` 返回同一套派生状态：

| 状态 | 显示的下一步 |
| --- | --- |
| 提案已冻结 | 队长启动对齐 |
| 对齐已完成 | 队长检查分工与标准并发布 |
| Codex 待执行 | 本人 take；领取后显示等待本人提交 |
| SciencePAL 待执行/运行中 | 本人保持 work，等待原运行和采集 |
| 等待输入 | 标明需要回答的成员及原线程 |
| 评审退回 | 队长按具体修改意见安排返工 |
| 未知启动 | 原成员核对原任务，不给出自动重发建议 |
| 项目暂停 | 队长恢复 |
| 全部通过 | 导出证据和核对科学结论，不再笼统显示等待任务 |

接口返回责任人、是否轮到本人、任务/运行 ID、平台，以及项目操作所需的当前 revision 和对象 ID。服务器独立鉴权。本人浏览器会话现可执行项目控制命令；任务领取、模型运行和成果交回仍通过本机成员入口。

## 恢复与可信边界

- 领取前保存本地 claimId；回执丢失时，重复 take **原目录**接回同一任务，不创建第二次执行。提交回执丢失时，原目录、原文件重复 submit；不同字节不能覆盖冻结成果。
- 本地输入被修改、目录属于另一成员/Host/项目、本人被撤销、结果属于旧版或任务已被重试替代时拒绝交回。暂停时本地新提交也会停止，恢复后使用原目录继续。
- 返工、新任务和新协议版本使用**新目录**。不要删除旧成果或重新领取来绕过权限；遗留 .lock 先确认对应进程已退出再处理。
- 本地结果仍经过 envelope、结果契约和独立评审。INVALID 由队长检查后 retry，不能覆盖原文件冒充已通过。
- Codex 回执单独记录 localExecution，SciencePAL 记录 thread/run/sandbox；不伪造远端身份。本地回执证明的是已鉴权成员交付记录，不证明具体模型、进程隔离或科学正确性。
- 旧 `sciencepal:call` 仍用于单人独立任务。其任意成果不会自动成为团队已批准成果；应通过分配到本人的任务包完成交付。尚无 MCP 安装、后台 Codex 模型守护进程或 DSH 接入。
- 本轮完成的是混合流程模拟，不是真实第二账号、真实跨平台模型质量验证或真人可用性研究。已有单账号真实 SciencePAL 案例继续保留，不将两类证据混称。

## 科研拓扑主界面（2026-10-30）

已有科研项目的房间打开根路径 `/` 即进入科研拓扑；`/sciencepal/team` 可直接进入。`/?view=software` 保留原软件协作界面，无科研项目的原房间默认行为不变。

- 成员节点显示项目冻结的平台绑定、本人身份与当前责任；平台与成员不混为一谈。
- 任务节点显示执行人、独立评审人、执行次数和审批状态。点击成员或任务，右侧展开原提案、范围、验收、成果和历次执行。
- 文件连线区分等待上游、已放行待领取/待回执、交接阻断、已交接。只有当前协议下游执行已完成回执校验（COLLECTED），且输入文件 ID 匹配上游获批成果，才标记已交接；仅创建任务或重名文件不算。
- 点击评审连线可查看失败证据、要求修正的内容和冻结成果；右侧“现在轮到谁”沿用 CLI 的同一待办模型，显示责任人与处理步骤。
- 版本选择可查看 R1/R2，归档页不提供旧版操作；断网保留上次快照并禁用处理步骤复制。移动端可切项目甘特，点节点自动跳到下方详情。
- 拓扑待办可直接确认发布、返工、裁决、重试、暂停/恢复和研究变更。Agent 运行仍由各自连接器或本地 Codex 完成；操作按钮不能代替模型执行。

可重复的只读模拟预览（在接入包根目录执行）：

```powershell
npm run build
npm run sciencepal:simulate -- --mixed
node apps/web/scripts/preview-research-topology.mjs
```

打开最后打印的本机地址。顶部可切“评审退回”“返工后完成”，所有模拟数据均有标识；文件下载对应实际模拟流程冻结的字节。保持预览进程运行，另一个终端可运行 `node apps/web/scripts/verify-research-topology.mjs`。浏览器检查使用 Windows 已安装 Chrome 的独立无头实例，不控制桌面、不读取个人浏览器状态。

拓扑初版验证：120 项科研回归测试通过（含 6 项交接语义检查）、20 项混合流程模拟检查、14 项实际浏览器交互检查；类型检查与构建通过。桌面 1440×1000、手机 390×844 已检查。真实第二账号联调与专业科研质量验证仍需独立完成。


## 在拓扑中操作完整研究流程

先按上文建立成员身份、绑定平台、提交提案并创建项目。本人运行 `npm run sciencepal:member -- panel`，使用返回的短期票据进入拓扑。初次接入仍需本机配置，各成员的 SciencePAL `work` 或 Codex 任务处理入口保持可用。

1. 队长在“现在轮到谁”点击“启动协议对齐”，确认后等待 Agent 返回协议。
2. “发布研究任务”会列出执行人、评审人和实际验收标准；确认发布后连接器自动接手。
3. 点评审连线查看退回证据，再点“查看返工待办”。“安排返工”自动带出评审要求，可补充说明，确认后保留旧版本并重新执行、评审。
4. 完成后直接打开证据清单。成员均可“提出研究变更”；影响评审结束后只有项目队长能确认应用，再发布新一版。
5. 裁决、失败重试、暂停和恢复同样在待办内处理。NEEDS_INPUT 仍由本人在 SciencePAL 原线程回答，未知运行由原连接器核对恢复。

按钮先展示具体内容，再由本人确认；取消不发送命令。提交中锁定重复操作，网络结果不明不自动重试；操作后刷新状态。发布后新任务自动进入画布视野。旧版本只读；表单打开后项目发生变化会要求重新检查。

浏览器仅获得科研项目控制能力：HttpOnly 成员会话、会话绑定的 CSRF 令牌、同源校验、服务端项目成员和队长校验、项目快照校验共同生效。旧版软件 API、Agent 绑定/领取/交回/恢复接口仍不接受浏览器写入。成员撤销后会话立即失效；不能利用另一个项目的队长身份控制本项目。已有 CLI 命令继续兼容。

另开终端可运行 `node apps/web/scripts/verify-research-controls.mjs`，对一个全新的模拟实例执行完整浏览器检查；测试完成后该模拟项目已进入 R2 完成态，想手动从头演练请重新启动模拟脚本。该检查使用独立 Chrome 无头实例，需要本机已安装 Chrome。

最新验证：126 项科研回归、20 项混合流程模拟、19 项实际浏览器控制检查通过。覆盖身份切换、普通成员权限、发布双击防重、提交失败反馈、取消返工、390px 返工表单、空变更拦截、R1 退回返工与 R2 重算及交接证据。R2 从 [1,2,3] 实际重算样本方差为 1；这证明流程正确，不构成科研专业优势或真实双账号验证。
