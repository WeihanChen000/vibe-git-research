## 实际完成路径

1. 从两个空白本机入口出发，分别绑定当前 Codex 和账号中真正可用的 SciencePAL Biology Agent。两端各自保存科研提案。
2. 在原项目弹层通过文件选择器上传 `iris.csv`，再载入 Iris 固定格式模板。上传与模板源文件哈希一致；随后在界面冻结提案并创建项目，没有用 create CLI 预建项目。
3. Codex 在原待办领取对齐任务，用冻结提案、源文件与结果格式生成研究协议；从原发布确认界面核对分工和交叉评审后发布。
4. Codex 实际 Python 读取 150 条 CSV，首版未获批候选只将第一行首值 5.1 改为 6.1。此受控错误在协议和 limitations 明示，原始 CSV 从未改写。
5. 真实 Biology 用 Python 逐行比较，发现唯一错误并 `request_changes`。原拓扑显示交接阻断。队长从同一待办安排返工，Codex 重读源文件修复；真实 Biology 第二次评审 5/5 通过。
6. Host 自动把获批 `data_audit.json` 交给 Biology 统计任务。首次统计计算正确，但只给出脚本文件名，没有按协议交付可复现代码。当前 Codex 独立复算后 5/6 通过，真实退回第 6 项。
7. Biology 根据原评审与队长补充重新实际计算，在 schema 允许的 limitations 中嵌入计算源代码与 Python 3.12.3 版本。Codex 再次从原始 CSV 独立复算，检查科学结论与代码计算逻辑，6/6 通过。原界面交回后自动完成。

## 发现与修正

- **返工反馈重复**：原界面预填的修改项与后端已有意见重复拼接。现在按已有意见逐行去重，保留队长另写/追加的要求，原始评审文件不变；覆盖预填、独立补充、末尾追加三种回归情况。
- **代码名不等于代码交付**：此次自然发现并真实退回。统一任务提示和队友说明增加要求：验收需要代码时，必须把实际代码与版本放进允许的交付字段；不能只指向本人沙箱。没有放宽原协议或替 Biology 改文件。
- **完成页误导操作**：去掉已完成项目的“暂停派发”；主拓扑、原菜单、右侧抽屉和成员权限保持原逻辑。
- **验证脚本精度**：科学解释由当前 Codex 阅读并绑定候选哈希，不能靠中文关键词白名单裁定；数值逐项独立复算。核对作者身份时同时匹配任务键与成果 ID，避免把上游附件误当成当前候选。
- **验证入口可靠性**：允许配置私有数据目录，启动失败返回失败退出码，避免失败被误报成功。
