# Vibe-Git 科研团队协作

让多位成员带着各自平台上的 Agent 参与同一科研项目，保留工作归属、研究依据与成果交接记录。

## Language

**成员（Member）**：参与项目、对自己的授权和交付负责的人；系统通过成员节点识别其操作。多个节点或 Agent 不自动证明有多个真实成员。
_Avoid_：把 Agent 数量称为人数

**执行平台（Platform）**：Agent 所在的运行环境，例如 Codex、DeepSeek Harness（DSH）或 SciencePAL。执行平台与底层模型是不同概念。
_Avoid_：把跨平台称为跨模型

**Agent 绑定（Agent Binding）**：某位成员授权用于团队任务的一项 Agent 能力，带有明确的成员归属和平台归属。平台上同一个共享 Agent 被不同成员使用时属于不同绑定。
_Avoid_：以裸 Agent ID 代表跨账号身份

**协作项目（Collaboration Project）**：成员围绕共同目标、冻结需求和交付规则开展的合作。成员日常入口可以不同，不改变共同项目的身份。

**研究协议（Research Protocol）**：对研究问题、证据来源、分析方法、假设、检验办法及结论边界的共同约定。
_Avoid_：把普通实现计划称为研究协议

**任务包（Task Package）**：某次具体执行所依据的目标、输入成果、研究协议版本和验收要求。

**执行回执（Execution Receipt）**：执行者对任务状态、实际输入、产出和运行来源的记录。成员声明与平台可验证证明属于不同证据强度。

**成果交接（Artifact Handoff）**：将特定版本、特定字节的成果交给下一项任务，保留生产者、接收者和评审关联。
_Avoid_：把聊天文本复制称为文件交接完成

**科研评审（Scientific Review）**：检查方法、证据和结论是否相互支持的评审，可提出修订，也可指出无法判断的事项。通过评审不等于证明科学结论为真。
_Avoid_：以代码运行成功代替科研结论成立

**工程验收（Engineering Acceptance）**：检查实现能否运行、测试是否通过以及交付是否满足工程要求的验收。

**跨成员评审（Cross-member Review）**：执行者和评审者归属不同成员的评审。跨 Agent、跨平台与跨成员分别记录，不能相互替代。
