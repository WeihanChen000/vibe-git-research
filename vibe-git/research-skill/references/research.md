# 科研协议与交付

按任务规模选用；简单复算无需完整论文计划。

## 提案模板

```markdown
# 研究问题
问题、研究对象及结论适用范围。

## 证据与输入
数据/文献来源、版本、访问条件；公开/私有/合成标记；固定文件哈希。

## 方法与基线
方法、参数、单位、对照及可能推翻预期的观察。

## 我的分工
本人 Agent、已验证能力、上下游依赖与交付文件。

## 验收
可复算的数值/容差或可追溯的证据标准；结论边界。

## 资源与停止条件
时间/成本上限、允许访问的来源、是否允许安装工具、失败记录方式。
```

## 结果包

通常包括原始输入引用及 SHA-256、实际命令与软件版本、重要参数和随机性（若适用）、机器可读结果、解释及局限、复现步骤、独立验收。负结果不能为了演示而删除。

现有 Host 继续校验冻结的 JSON Schema 和回执格式。若 schema 不允许新增字段，用已允许的证据字段或另外声明的附件承载，不能自行改变 schema。流水线禁止联网的任务使用冻结来源附件；联网文献任务须由真实执行入口与任务授权允许，不能凭 Skill 扩权。

## 评审例子

结构分析可核对：坐标和显示单位、模型/链选择、原子/残基标识、参数敏感性、静态几何与功能推断的区别。可视化本身不能证明药效或结合能力。

文献分析可核对：每项主张的来源及定位、检索范围、全文可用性、发现性搜索与系统性综述的区别。不能编造引用，也不能把未读全文标为全文证据。

这些是示例，不要求所有任务机械套用。执行者提交候选成果，评审者按冻结标准给出证据，成员最后确认。任何 Agent 的批准均不构成科学认证。

## 原流程映射

| 原协作动作 | 科研含义 |
| --- | --- |
| 需求提案 | 研究问题、证据、方法及个人分工 |
| 自动对齐 | 冻结研究协议，裁决方法/数据/指标冲突 |
| 开发任务 | 证据整理、计算、实验分析、独立复现 |
| 测试与评审 | 工程可执行性与科学合理性分别验收 |
| 需求变更 | 协议修订及受影响结论重新核验 |
| 合并交付 | 带来源、参数和复现记录的成果包 |

跨平台能力是执行层扩展，不改变成员身份、提案归属和验收权。
