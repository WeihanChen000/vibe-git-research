## 为什么推进这个案例

此前的 14 → 15 合成求和例子证明退回机制，但不能说明 SciencePAL 在实际研究资料中的用途。本轮使用有许可的公开科学数据，让一个 Agent 审计来源、单位和原始记录，另一 Agent 独立统计，再互相评审。数值可由独立脚本验证，评委也能理解具体交付物。

这证明的是对公开历史数据进行可追溯复核的工程能力，不是新的科学发现，也不是任意科研任务的可靠性保证。

**未复现的单位故障。** 最初提案希望作者首轮输出错误元数据 mm、被退回后改成 cm，但作者第一次就给出 cm。独立检查明确保存 `plannedFaultTest.status = NOT_REPRODUCED`、`unitRejectionObserved = false`。没有手动篡改成果或评审来制造失败。原提案和原始成果仍保留，其中提及“受控故障测试”的文字描述的是原试验意图，不能当作实际发生故障的证据。项目显示名改为“来源与单位审计”，当前可复用模板也改为正常复核。真实退回链仍请使用 [SCIENCEPAL-REWORK-LIVE.md](SCIENCEPAL-REWORK-LIVE.md) 中的独立项目。

**输出类型尚未强制保持。** 实际 rows 是 CSV DictReader 风格对象、数值为字符串，而最初提案示意二维数组；范围重叠输出为包含两个范围的对象，而不是单个布尔值。发布后的验收只约束语义，独立脚本严格解析数值并逐行核对，没有假称 JSON 类型与原提案完全一致。本轮加强了后续对齐提示中的字段/类型保留要求，但尚不能替代机器可校验的成果 Schema。这是下一项有价值的协议优化。

## 本次新增的通用能力

1. 新建项目支持单个不超过 256 KiB 的 UTF-8 源文件、来源与署名；冻结后贯穿对齐、执行、评审及返工。包含非法名称、编码、大小和字节篡改校验。
2. 内置 Iris 模板从本地静态文件加载，并核对固定 SHA-256；可替换为用户自己的文件和提案。上传的内容会发送给所选 SciencePAL Agent，界面对此有明确说明。
3. 证据回顾展示源文件出处、下载及校验信息；对象数组显示为表格，符合花瓣统计结构的实际结果显示范围图，无预置成功数据。
4. 首轮对齐超过验收上限被正确阻止；后续提示明确 1–8 条验收并要求保留约定字段。该提示调整尚未另开远端运行验证。

## 下一步决策

当前已从纯机制演示推进到真实公开数据复核。下一优先级是保留并执行明确的成果类型约束，以及让错误恢复更易解释；随后邀请一个研究使用者评估验收标准和操作负担。不要继续用提示词“要求模型故意犯错”冒充稳定故障注入，也不应扩大平台范围来掩盖这些缺口。需要严谨的负向研究案例时，单独设计透明标注的错误输入夹具，保持原始数据、预期错误与真实评审相互可区分。
