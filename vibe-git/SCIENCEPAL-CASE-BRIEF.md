# 一份科研成果，怎样可靠地交给另一个人的 Agent？

Vibe-Git 让每个人保留自己的成员身份和 Agent，由同一份研究协议约定分工、评审和文件交接。队长负责发布与返工；作者提交成果，另一成员独立评审；获批文件才放行给下游，交接回执确认实际收到的版本。

## 本例研究什么

使用公开蛋白结构 **1CRN**，复算三个二硫键的距离，再计算溶剂可及表面积（SASA，即溶剂能够接触的表面积）。这是可复现的计算核验，不是新的生物学发现。

- **Codex**：解析结构、计算距离；最后用独立 NumPy 算法复核表面积。
- **SciencePAL Biology**：独立评审几何结果；在科研环境中用 BioPython 计算表面积，交回代码、参数与工具版本。
- **Vibe-Git**：保留失败版本、执行评审门禁、传递获批文件、核对回执、在等待输入后接回原线程。

## 按什么顺序看

当前演示默认展示最终专业证据；点“从头播放”或选择首个“单位错误被退回”检查点查看完整过程。这是可选案例，真实工作区可新建自己的课题。依次观察：**退回 → 修正与复审 → 文件放行 → 等待参数 → 原线程接续 → 收到文件 → 最终通过**。选择阶段或自动播放；点击节点、交接连线、顶部入口可查看原始证据。

## 专业能力由什么支持

真实 Biology 运行提供了 BioPython 1.84、Shrake–Rupley 算法、1.4 Å 探针和可复算附件。结果为 **2970.152 Å²**；Codex 独立基线为 **2973.163 Å²**，差异 **0.101%**，满足预设 3% 容差。支持的是科研环境与工具链确实可用，不是模型优劣排名。

## 哪些已经验证，哪些还没有

这次是 **同一用户的 Codex 与 SciencePAL 真实执行**，两个工作流身份，不是真实双账号实验。单位错误和等待参数是明确设计的闭环测试。七阶段中六个是原始快照，接续瞬间依据真实回执重建并单独标注。真实双账号还需队友在自己的电脑与账号接入验收。

准备接入时，打开原顶部“邀请成员”；真正工作区的“当前成员 → 队友接入说明”也能查看步骤。回放只读，不需要 Key，也不会调用模型。
