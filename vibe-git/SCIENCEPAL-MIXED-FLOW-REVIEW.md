# 同项目 Codex × SciencePAL 协作复核

2026-10-30。继续使用原版拓扑、算力网与右侧待办；验证重点是本人任务包、文件交接、交叉评审、返工和等待输入后的接续。

## 已完成的优化

- Codex 本人待办增加“准备本人任务包”和“检查并交回成果”。路径与成果文件名由本机入口根据已鉴权的冻结运行确定；浏览器只提交项目与运行 ID，不能指定任意文件读写路径。原 Host 继续检查身份、平台、运行、claim、版本和成果回执。
- 稳定任务目录避免重复领取；每次返工使用新的运行目录。CLI 已领取的任务不会被网页接管，仍保留原目录 submit。准备文件不调用模型，用户把说明交给本人 Codex 执行。
- 未检测到成果时交回按钮禁用；格式错误留在原运行上修正。旧成果与文件指纹不被覆盖。任务文件位置折叠显示，复制说明与交回按钮留在原操作区域。
- 修复网页与环境脚本可能使用不同 SciencePAL 日志的问题。共用 memberJournalPath 规则，兼容有效旧日志，拒绝冲突或其他身份的日志；VIBE_GIT_RESEARCH_PROFILE 也被环境脚本采用。
- 去掉“连接器在线尚未监测”的过时提示；Codex 的入口无心跳不再被当成执行阻断。操作成功提示明确表示命令已提交，实际进度仍看任务状态。
- 新任务包按对齐、执行、评审、变更评审解释提交后的决策关口；旧任务包仍按原版本重放，不覆盖旧 TASK.md。

## 完整演练结果

1. Codex 成员在原待办准备对齐任务包，冻结输入逐文件 SHA-256 一致，未写成果时不能交回。
2. 确定性合成计算写入对齐稿后，经真实本机入口交回，队长检查并发布。
3. Codex 执行上游任务；故意交回缺少 envelope 字段的文件被挡在原任务，修正格式后进入另一成员的 SciencePAL 评审。
4. SciencePAL 评审进入 NEEDS_INPUT。界面显示本人责任、原线程和回答入口。
5. 停止连接器，模拟本人从网页回答原线程，再重启连接器。Host 记录一次 sciencepal-web 续接；线程未变、运行 ID 更新，没有重复发送答复或重新 start 评审。
6. 评审读取上游真实文件字节，发现单位缺失并退回；下游分析尚未派发。
7. 队长安排返工，Codex 准备新目录、修正单位，旧目录中的拒绝版本保留。
8. 复评通过后，SciencePAL 下游拿到的输入 artifactId/SHA-256 与上游获批文件一致。
9. Codex 在本人任务包中独立复评下游结果，同项目所有任务通过。Codex 执行记录只有本地执行标识，不伪造 SciencePAL 线程。

## 使用方式

普通成员按 FIRST-RUN 接入即可。Codex 成员从右侧待办准备任务包并交给本人 Codex，生成成果后回到同一待办校验交回；SciencePAL 成员保持本人连接器运行。等待输入时在本人 SciencePAL 原线程回答，连接器接回原任务；UNKNOWN 仍要求人工核对，不能靠换目录或重发绕过。

演练启动：构建后运行 `node apps/host/scripts/preview-research-mixed.mjs`。这是隔离的合成项目，没有自动 Codex worker；验证脚本会从冻结包生成合成输出并通过真实界面交回。它不使用真实 Key，不影响已有科研项目。
