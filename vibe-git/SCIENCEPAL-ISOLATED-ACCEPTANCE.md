# 不找队友，也能验收真实协作

这个入口运行一个队长、两个成员的独立项目身份，使用现有 Codex 登录和一个 SciencePAL 账号。身份、任务目录和连接器日志分别保存；它不是三个真人、跨账号验证或操作系统安全沙箱。

## 最短路径

在 `vibe-git` 目录完成一次 `npm ci`、`npm run build` 后：

- **只看已有真实记录**：`npm run research:replay -- --isolated`，从原拓扑案例下拉框选择“三成员 · 真实恢复与权限验收”。不调用模型。
- **离线检查公开证据**：`npm run test:isolated-acceptance`。核对文件哈希、原始输入回执、返工顺序和交接版本，不执行附件代码。
- **离线演练故障流程**：双击 `acceptance.cmd`，或 `npm run research:acceptance`。先跑合成执行器的故障演练，再核验公开真实记录及篡改拒绝测试。两类结果明确分开，均不调用模型。
- **用自己的现有账号重新跑**：`npm run research:acceptance -- --live`。会使用真实模型额度；自动发送的答复只适用于这份预先约定的验收案例。

真实验收默认复用 `%LOCALAPPDATA%/VibeGit/sciencepal-auth.json` 的 `apiKey`，也可通过 `SCIENCEPAL_AUTH_FILE` 指向项目外已有认证文件。Codex 必须已经登录。本例需要本机可用 Python（独立复算可用标准库或已安装 NumPy），以及 SciencePAL Biology 沙箱中可用的 Biopython；缺失时会如实停止，不自动安装。不要把密钥写入源码、提案或命令行参数。

## 它实际做什么

1. 创建三个不同成员身份，以及一个不参与项目的权限测试身份。
2. 队长 Codex 对齐提案并冻结公开 1CRN 坐标、方法、单位、结果格式和数值检查。
3. 成员 SciencePAL Biology 执行真实计算。连接器保存远端回执后主动退出一次，新进程从日志恢复，不重发远端任务。
4. 远端按预先安排提出问题并进入真实等待输入。脚本发送事先授权的测试答复，续接原线程。
5. 首轮只做 100 点先导试算，队长 Codex 按最终精度标准真实退回。队长按反馈安排返工，SciencePAL 进行 1000/5000 点计算。
6. 数值检查和独立复审通过后，成员 Codex 领取获批文件做汇总，队长再次复核。
7. 对已冻结的真实 Codex 成果做一次受控重传：服务器接收后丢弃返回，按原任务目录重试，检查成果 ID、哈希和项目状态均不变，不再次启动模型。
8. 核对未参与成员不能读取、普通成员不能发布/返工、别人不能冒领或代交，以及恢复没有产生重复远端提交。

这是预设退回和故障注入，不能用来估算自然错误率或人工节省时间。平台仍是通用科研流程；1CRN 只是验收样例。

## 中断后怎么办

私有状态默认保存在 `%LOCALAPPDATA%/VibeGit/isolated-acceptance-20261031`，不会进入仓库。重新执行同一个命令复用原项目，不重建任务。要查看进度：

```powershell
npm run research:acceptance -- --status
```

脚本只允许一个真实验收进程。若整个终端意外退出留下 `acceptance.lock`，先查看其中 PID，确认原进程已结束，再仅删除该锁文件。不要清空成员日志或任务目录。

SciencePAL 已取得回执的运行可以恢复；如果本地 Codex 留下 `RUNNING` 记录但原进程已退出，脚本会停下要求检查原任务，不猜测成功或重复计费。真实模型返回不合格式、未触发提问或不同的科学结论时，保留实际失败，不能为了凑齐验收把状态改绿。

如需新一轮，设置 `VIBE_ACCEPTANCE_ROOT` 为另一个**项目外**绝对目录。已完成目录只核验/导出，不再次调用模型。

## 导出回放

真实流程完成后运行 `npm run research:acceptance:export`。只从已记录的快照生成原拓扑回放，保留原始附件字节；发现密钥字段或本机用户路径即停止导出，不静默改写哈希。发布前仍需检查文本和科学结论。

再运行 `npm run test:isolated-acceptance` 和 `npm run build`，最后 `npm run research:replay -- --isolated`。回放不接触账号，不提供修改项目状态的操作。

## 结果正确、但评审缺证据时

在原拓扑“现在轮到谁”中，队长可以选择“补充证据复审”，填写来源、原任务/线程与能支持的事实。它保留原成果字节、数值检查和退回记录，交给原独立评审者判断；同一份成果仅允许一次。数值或方法错误仍要返工。执行上限仍为三次，达到上限后不能靠反复点击绕过。

本次公开记录经过三次退回，最后由操作者核对 SciencePAL 原线程的提问与计算工具顺序后补证。它不是全程无人介入的一键成功录像。新运行的协议已把科研验收与故障测试分别说明，减少把测试事件误加成科研交付要求的漂移；既有案例的冻结标准没有修改。

若真实验收在第三次退回后只缺首轮顺序证据，先核对原线程，整理项目外 JSON 记录（`source: operator-observed-sciencepal-ui`、原 `threadId`、有来源的 `events`）。设置 `VIBE_ACCEPTANCE_EVIDENCE` 指向该文件后运行原命令，只允许一次补证复审；它不会新增第四次计算，也不会自动批准。不要为通过测试编造记录或复用别的线程。
