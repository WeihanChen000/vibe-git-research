# 多个人，各自的 SciencePAL Agent

更新：2026-10-29。已完成成员连接器、权限接口和只读面板；真实第二账号尚未接入。本机现有账号已通过连接器核验 Agent 可访问性，并绑定到原队长节点；当前面板如实显示一位成员、零个多人项目。

## 原生能力核查结论

| 问题 | 证据与结论 |
| --- | --- |
| 能否把 Agent 分享给别人？ | **支持，官方明确说明。** [智能体指南](https://sciencepal.ai/help/agents)说明可按邮箱分享自定义 Agent，接收者在「共享给我的」中使用；可以停用、删除分享规则。不能把此功能算作我们的创新。 |
| 能否分享对话？ | **支持公开查看。** [对话指南](https://sciencepal.ai/help/conversation)描述无需登录的公开对话链接，支持取消分享。该说明不等于共同编辑或共同执行。 |
| 能否跨会话复用文件？ | **支持。** [工作空间指南](https://sciencepal.ai/help/workspace)说明「我的资料」、项目保存版本和发消息时选择文件。这里的跨会话不能直接推导为跨账号共享项目。 |
| 能否通过 API 使用自己的 Agent？ | **支持。** [SDK 指南](https://sciencepal.ai/help/sdk)给出账号权限内的 Agent、任务和沙箱文件调用。 |
| 两个账号能否共同编辑同一项目、接续同一执行、共同管理成员权限？ | **未确认。** 本次查阅指南及已登录工作空间，未取得这些能力的直接证据；这不是证明平台没有这些能力。 |
| 被分享 Agent 的任务计费、运行归属、私有知识库/记忆是否随之共享？ | **未验证。** 不从「Agent 可分享」推断这些权限；需两账号验证或平台说明。 |

本次未添加分享规则、公开任何对话或邀请他人。用户选择先交付连接器及说明，随后由队友接入。

因此产品定位收敛为：**复用 SciencePAL 的科研执行能力，把多位成员各自的提案、Agent 执行、交叉评审与版本交接组织成团队流程。** 不宣称首创多 Agent、跨账号 Agent 分享、文件哈希或评审机制。

## 已接入原 Vibe-Git 的内容

- 使用原 `CollaborationNode`、Bearer 随机凭据、撤销机制、邀请与浏览器会话；不信任请求里的 `x-member-id`。
- 提案仍写入原 `/api/v1/plans`。只有作者能修改，队长也不能代改；更新必须匹配当前版本。
- 队长选择 2–4 位不同成员的当前提案，冻结文档 ID、作者、修订、原文及哈希；旧版本或撤回的提案不能用于新建。
- 成员用自己的 SciencePAL Key 验证可用 Agent 后登记绑定。项目冻结该映射，之后重新绑定不会改变已经发布的项目。
- 对齐、冲突裁决、发布、暂停、返工、确定失败的重试、应用变更由队长操作；项目成员可提交需求变更。操作人写入时间线，变更保存提出人。
- 任务、评审、对齐均绑定成员。连接器只能领取本人成员的运行，只执行启动命令指定的一个项目。
- 成果仍经过原来的输入字节回执、需求版本、可选成果格式和逐项评审校验。评审通过后才能交给下游；退回、旧输出和 R1 证据保留。
- `/sciencepal/team` 使用原浏览器会话展示成员、提案归属、冻结版本、执行/评审人、文件和时间线。修改操作走本机 CLI，与原项目模式一致。
- 旧 `/sciencepal` 仅展示历史单账号项目；不能绕过成员认证操作多人项目。

## 数据与权限边界

```text
成员 A 的电脑                         Vibe-Git Host                         成员 B 的电脑
Vibe-Git 凭据 A ─── 提案 / 领取 ────► 成员身份、冻结提案 ◄──── 提案 / 领取 ─── Vibe-Git 凭据 B
SciencePAL Key A                     需求版本、评审与成果                    SciencePAL Key B
        │                                   │                                      │
        ▼                                   │                                      ▼
SciencePAL 账号 A ── 指定成果原始字节 ───────►│──── 已批准成果 / 任务上下文 ──► SciencePAL 账号 B
```

Host 不接收 SciencePAL Key，不用队长的 Key 代替其他成员执行。成员本机日志包含任务输入、远端 ID 和待回传结果，不包含 Key；它和凭据仍应保存在项目外。

**信任边界：**成员凭据证明 Vibe-Git 节点身份，不证明自然人身份或 SciencePAL 账号唯一性。远端 Agent/沙箱 ID 由成员连接器使用自己的 Key 查询并回传，Host 并无平台签名证明；恶意成员能伪造回传。当前适用于互信的小团队，不能宣称零信任执行认证。不同成员节点也不能自动算作两个真实账号。

2026-10-30 已支持不同成员使用同一个内置/共享专家 ID：新项目中的 agent.id 是按成员生成的工作流绑定 ID，runtimeAgentId 是冻结的 SciencePAL 调用 ID。分工、评审和权限按成员绑定区分，连接器只用 runtimeAgentId 调用平台。旧项目省略 runtimeAgentId，保持原 ID 语义。独立性不等于账号所有权证明，双账号实测仍待队友接入。

## 防重与恢复

- 每次领取写入独立 claimId；相同请求可重试，另一个连接器不能再次领取同一运行。
- 连接器在发起 SciencePAL 前原子保存 SUBMITTING 日志。若请求结果未知，或在该状态重启，进入 UNKNOWN，绝不自动再次提交。
- 已取得的线程/运行 ID、已下载成果先保存本机，再回传 Host；回执丢失可原样重传，不能换成另一份文件。
- Host 在提交中重启也会阻止重发；原成员可回传已保存的远端 ID。未知提交需要人工核对线程，再使用 `recover`。
- 明确失败或格式不符可由队长显式 retry。新运行清除旧 claimId，保留失败证据。
- 暂停停止新领取；已经提交给 SciencePAL 的任务仍会完成。撤销成员阻止后续领取与回传，不会远程终止该成员的 SciencePAL 任务。
- 本机 `.lock` 防止同日志同时运行。强制杀进程后如残留，确认对应进程已退出再人工删除该 `.lock`；不要删除任务日志以试图重发。
