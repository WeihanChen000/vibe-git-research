## 定位与优劣

一句话定位：**为 SciencePAL 多 Agent 任务提供可追溯的交付流程，让成果经独立评审后再交给下游。**

| 维度 | 已有优势 | 仍需补足 |
|---|---|---|
| 核心价值 | 不止并行对话：有共同验收、文件依赖、独立评审、退回返工和版本重编排 | 必须用具体研究场景解释这些约束如何节省返工，不能仅展示流程组件 |
| SciencePAL 使用深度 | 两个真实 Agent、多次真实执行、独立线程与沙箱、真实文件交接 | 当前单账号、JSON 文件任务；没有跨账号团队授权，也没有支持任意科研工具格式 |
| 完成度 | 成功路径、需求变更后重跑、退回修复后重审均有真实证据 | 等待追问的续聊流程、长时间初始化及连接异常恢复还不够完整 |
| 可信度 | 不可变文件、SHA-256、原始输入回执、独立 Agent 和沙箱检查、下游派发时序 | 哈希证明字节一致，不证明科学正确；评审结论仍来自模型，不能保证识别任意缺陷 |
| 展示 | 成果流向、轮次与版本切换、修订对照、交接检查；已增加真实 UCI Iris 复核、统计表及范围图 | 尚无实际研究用户或专家评估；Iris 是历史描述性案例，不能据此证明广泛科研价值 |
| 交付 | 本机应用可演示，证据可以导出，原 Codex 工作台仍保留；用户已确认原作者为队员 | 需整理团队既有/新增贡献、最终共享范围和评委可访问入口；本机地址不能直接交给外部评委 |

判断：已有可以现场演示的完整工程闭环，最有辨识度的是“错误被退回且不会继续污染下游”。公开数据案例把流程落到来源、单位和统计复算；新增冻结格式又使交付类型可被机器强制检查，且已用新真实运行验证。仍不足以宣称已验证广泛科研实用性，下一项产品证据是研究使用者的实际评估。

## 本轮决策与实现

优先完成两件事：把真实协作证据变成评委可以操作的界面；让现场查看历史不依赖远端临时响应。未扩展新平台、引入依赖或复制外部源码；本轮局部实现不触发 GitHub 复用检索。

### 真实运行回顾

- 默认进入回顾视图；协作工作台保留原发布、返工、变更及恢复操作。URL 记录项目和视图，刷新后保留入口。
- 左侧成果任务显示依赖、作者及评审者；右侧可选择任一次执行，查看原始评审、逐项验收与文件。
- 自动从实际 JSON 找出修订字段，展示旧值和新值。`reported_total: 14 → 15` 来自本机真实文件，不是预设演示文字。
- 下游任务核验交接文件是否匹配、批准是否早于派发、评审是否独立。缺失门禁不能获得整体通过标记。
- 可切换当前及归档需求版本。完整报告以 JSON 下载，包含成果结果、运行及输入文件索引、评审、哈希和交接检查；这是报告，不是包含所有原始输入字节的离线证据包。
- 查询接口 `GET /api/sciencepal/projects/:id/evidence?revision=N`；添加 `download=1` 下载报告。接口只读取本机数据，重新验证冻结字节，不调用远端 Agent。

### 演示可靠性

- 本机连接和远端 Agent 可访问性分开。打开历史不再先请求远端 Agent 列表；新建项目时才检查远端，并可手动重试。
- 本机请求有超时；避免重叠轮询。断线保留已加载记录，明确标为旧快照，禁止提交新命令。
- 服务恢复后自动同步；不会通过刷新重复创建远端任务。
- 历史报告读取失败清除该视图内容并提示重试，不能沿用未核实的通过标记。
- 响应式布局、键盘焦点可见；没有自动播放虚构进度或依赖外部字体、媒体加载。

设计：延续现有绿色协作品牌，采用实验记录的文件流向与核验结构。主色 #182E3C，批准色 #136E63，修订色 #B75B2B，背景 #F3F7F8，白色 #FFFFFF，分隔线 #CAD8DD。标题使用系统 Bahnschrift/等线，正文沿用 Segoe UI/微软雅黑，字段使用 Consolas。视觉重点是实际“旧值 → 新值”；首轮截图发现信息过高，随后收紧头部并将真实修订摘要前置。

## 三分钟演示路线

**0:00–0:25：问题与定位。** 打开 Iris 来源与单位审计，展示冻结的真实公开数据、来源署名与两个 Agent 分工。说明平台把验收和文件版本放在交接之前。

**0:25–1:10：展示科研交付。** 选择 species_summary，展示实际范围图及统计表：150 行、三个物种各 50，后两类范围重叠。指出独立评审与文件交接检查，说明本机另做了独立数值复算；这是历史数据复核，不是新发现。

**1:10–1:50：展示失败和修复。** 切到“真实退回返工验证 · 错误总和修复”，明确这是独立的合成故障案例。先看首次退回，再切第二次通过，展示实际 14 → 15、原数据与 nonce 保留、验收未改变、旧文件可下载。不能说 Iris 发生过单位错误退回。

**1:50–2:20：展示交接。** 选择 consume_sum，看到最终 mean=3，以及文件一致、先获批后派发、独立沙箱三项证据。这里解释平台的价值：一次失败不该继续污染后面的分析。

**2:20–2:45：展示需求变化。** 选择另一个真实项目，切换 R1 与 R2；说明需求经评审和确认后重新对齐，旧成果归档，新版本重新执行。

**2:45–3:00：交付与边界。** 点击导出报告，指出可以进一步检查原始证据。说明当前是单账号本机原型，公开数据数值验证已完成，下一步要验证真实研究使用者的操作负担与价值；尚无节省人工返工的量化结论。

现场主线使用已完成真实记录。若展示实时执行，应事先检查 Key 和远端连接，并预留初始化等待时间；历史回顾不会产生新的调用费用。不要把历史回顾称为实时执行。

## 下一阶段优先级

1. **使用者验证。** 公开数据案例及冻结成果类型已完成真实验证（新项目 5 次运行、44 项独立数值/来源/类型检查、55 项通用证据检查通过）。邀请研究使用者检查验收标准与操作负担。需要故障案例时，透明标记错误夹具，不能靠提示要求模型犯错后就预设失败已发生。记录实际缺陷、人工介入次数和运行耗时，不捏造提升比例。
2. **补齐异常交互。** 优先验证 NEEDS_INPUT 的安全续聊绑定、长时间初始化提示和有界恢复；未知提交仍不能自动重发。
3. **交付准备。** 明确上游授权与比赛提交要求，整理可以公开的素材、录屏和说明。处理完成之前不公开部署当前私有副本。

不建议现阶段抢做更多 Agent 平台或完全自动批准：它们会分散演示主线，也没有解决上述最重要的证据缺口。
