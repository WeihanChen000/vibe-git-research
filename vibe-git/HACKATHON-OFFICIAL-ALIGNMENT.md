### 现在调整开发优先级

1. **先保证可提交、可访问。** 核对提交表字段及 SciencePal 作品分享方式，用独立访问视角检查权限。localhost 不作为评委入口；私有线程链接未经核验不称为共享链接。原作者为队员，按团队成果整理代码及展示材料，同时写清各人的贡献和共享范围。未经明确指示不代发消息、不发布代码、不提交参赛表。
2. **补科研问题的证据。** 选定“研究表格从数据审计到统计报告的交付错误”作为现阶段具体场景。优先请一位实际研究使用者检查流程与验收标准。若暂时没有用户测试，说明尚未验证真实研究使用价值，不捏造访谈、节省时间或错误检出率。
3. **完成有限、可解释的对照。** 对已有原始结果说明格式漂移，以及新规则怎样处理数字字符串、对象/数组变化、缺字段和额外字段。明确自动测试负向样本与真实远端运行的区别；已有合成求和返工案例单独标注，不冒充 Iris 科研错误。
4. **制作规定材料。** 先锁定五页内容和四分钟脚本，再录制实际页面，最后对照提交字段核验。核心流程已有运行证据，此时不优先扩展平台、增加 Agent 数量或进行大范围界面重构。
5. **恢复功能作为次优先。** NEEDS_INPUT 安全续聊仍有价值，但只有它阻碍代表性演示时才排到提交材料之前。当前完整成功记录可以承担演示主线，明确标为已完成真实运行回顾。

## 五页说明的内容安排

1. **研究痛点与使用者。** 数据审计、统计与复核分交给不同 Agent 后，数据、单位、结果类型或需求版本可能不一致。说明适用场景，明确已有证据和待验证的用户价值。
2. **工作方式与 SciencePal 作用。** 冻结提案/原数据/格式 → 对齐和确认 → 执行 → 机器检查 → 独立 Agent 评审 → 交接；退回和需求变更分支。标出哪些运行实际在 SciencePal 完成。
3. **真实公开数据实例。** 新 Iris 项目、两 Agent 的实际分工、150 行数据、统计图、来源和交接证据。旧/新输出类型对照，不能将格式通过等同于科学正确。
4. **验证与失败处理。** 分开列自动测试、真实成功、真实需求变更、真实合成错误返工。给出精确口径，保留本次没有发生错误的事实，不虚构成功率或效率收益。
5. **新增贡献、局限与复现。** 原 Vibe-Git 与赛事新增工作边界；单账号、文件任务、受限格式及人工确认；实际资源声明、可访问链接、下一步研究用户测试。
