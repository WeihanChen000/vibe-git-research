# 从原版拓扑加入科研协作

**最新入口：** [队长 / 队友分步接入](SCIENCEPAL-TEAM-START.md) · [原拓扑真实案例回放](SCIENCEPAL-REPLAY.md)。解压后 `open-replay.cmd` 可先看已完成的单账号真实记录；`open-research.cmd` 才是本人接入与新任务入口。

2026-10-30。复用原版顶部工作区、算力网、邀请、我的提案、成员卡片和右侧抽屉；研究任务、独立评审与文件交接显示在同一张拓扑里。这里是推荐的图形入口，旧 CLI 仍可用于诊断与 Codex 任务包。

## 队友：安装一次，以后双击启动

1. 解压队长提供的同版本源码包，安装 Node.js 24+。首次安装依赖需要网络。
2. 在解压后的 `vibe-git` 文件夹双击 **open-research.cmd**。首次会运行 `npm ci`、`npm run build`；后续复用构建。也可在终端运行 `node scripts/open-research.mjs`。它不修改系统执行策略、不安装后台服务。
3. 启动脚本会尝试自动打开本人页面；浏览器没有打开时，使用终端打印的备用链接，并保留终端运行。链接两分钟内单次有效；过期后重开入口。不要把该链接发给队友。
4. 在“加入协作房间”粘贴队长的完整邀请链接。每个人加入一次，已有身份会保留。
5. 点顶部 **算力网**，选择 SciencePAL，输入本人 Key，点“验证账号并读取 Agent”，选择本人可用的专家，再点“接入算力网”。Key 验证后清空输入框，只保存在本机个人目录，不交给队长。Codex 成员直接选择 Codex，不填 Key。
6. 接入成功后点 **提交我的提案**，或从顶部、工具栏、本人成员卡片进入。写研究问题、数据来源、方法、交付与验收标准并保存。切换入口会保留当前页面内的未保存草稿；关闭或刷新页面会触发离开提示。另一窗口改过提案时不会覆盖当前草稿，先核对再明确放弃或重新编辑。保存后页面会提示等待队长建立研究。
7. 队长建立项目后，SciencePAL 成员在 **算力网 → 启动本人连接器**。网页保留当前身份，后台子进程只执行本人在该项目中冻结的任务。重复点击不会启动第二份。
8. 点 **现在轮到谁** 或成员卡片，按右侧责任人和具体阻塞处理。轮到本人 SciencePAL 任务时，可直接点 **管理本人连接器** 返回原算力网入口；账号配置在接入后折叠，启动按钮保持易见。可在算力网停止、重新启动本人连接器；保留同一入口与日志，启动后核对原运行，避免另开一份 CLI worker。

以后再加入同一房间：直接双击启动，身份、绑定、Key 和连接器日志继续复用。应用升级替换源码后先运行 `npm ci` 与 `npm run build`；不要删除个人目录。一个本机入口同时管理一个项目连接器，换项目先停止当前连接器。

## 队长：建房、邀请、发布

1. 首次 `npm ci`、`npm run build`，一个终端执行 `npm run sciencepal`，保持 Host 运行。
2. 另一终端执行 `node scripts/open-research.mjs --captain`，打开本人链接。也可构建后用 `npm run research:open -- --captain`。默认读取本 Host 的队长身份，不重新注册队长。
3. 顶部 **邀请成员** 复制房间邀请。跨电脑必须使用队友可访问的 HTTPS Host；本机 localhost 邀请不能发到另一电脑使用。已有的隧道配置与启动方法见 [队长生成跨电脑邀请](SCIENCEPAL-TEAM-QUICKSTART.md#3-队长生成跨电脑邀请)，本机入口不会自动开放公网。
4. 双方分别接入算力网并保存提案。点 **对齐并建立研究**，选择 2–4 位已准备成员（含队长），冻结提案与各人的执行平台。
5. 右侧待办 **启动协议对齐 → 检查研究协议 → 发布研究任务**。若有分歧，队长先裁决。模型不能替队长发布。
6. 评审不通过时点对应评审，查看具体修改项，在待办 **安排返工**。连接器执行、独立复评、下游文件字节回执均在同一拓扑更新。全部通过后打开证据清单。

建立项目之后更换算力绑定不会修改已有项目的冻结平台；为新组合建立新项目。需要预置公开 1CRN 数据和专用成果契约时，仍使用 QUICKSTART 的 prepare/create 专业案例模板；通用图形建项不会自动上传本机数据文件。

## Codex 成员如何执行

推荐直接在原右侧 **现在轮到谁** 待办操作：

1. 点 **准备本人任务包**。在本人个人目录生成 TASK.md、冻结 inputs 与约定的成果位置，不会启动模型。
2. 点 **复制给 Codex 的任务说明**，交给这台电脑上的本人 Codex。让它读取任务包、完成计算或独立评审，并把完整 JSON envelope 写到指定成果文件。
3. 页面检测到文件后，点 **检查并交回成果**。格式或输入回执不正确时留在原任务上修正；通过后进入对应的评审或队长确认。
4. 返工会分配新任务包和新目录，旧成果保留。如果已经用 CLI 领取，继续使用原目录 submit，网页不会抢占或创建第二份领取。

“本次任务文件与保存位置”可展开查看路径。页面上的连接心跳只描述入口/连接器，不把未打开网页误判为 Codex 无法继续执行。

算力网里的 Codex“已接入”表示成员平台绑定，**不表示网页已启动 Codex 模型**。在本人 Codex 终端配置同一身份（普通队友不加 `-Captain`）：

```powershell
.\scripts\sciencepal-member-env.ps1 -Captain
npm --silent run sciencepal:member -- next PROJECT
npm --silent run sciencepal:member -- take PROJECT C:\你的个人目录\task-001
```

让 Codex 阅读返回的 TASK.md 与 inputs，计算或评审并按契约交回。新任务使用新目录：

```powershell
npm --silent run sciencepal:member -- submit PROJECT C:\你的个人目录\task-001 C:\你的个人目录\task-001\data.json
```

PROJECT、目录和输出文件名用实际值，输出格式以 TASK.md 为准。默认个人目录与图形入口一致；自定义目录时，环境脚本的 `-ProfileDir` 必须与 `VIBE_GIT_RESEARCH_PROFILE` 相同。任务包详细规则见 [混合团队说明](SCIENCEPAL-MIXED-TEAM.md)。

## 如何读在线与阻塞

| 显示 | 含义与处理 |
| --- | --- |
| 本人本机入口在线 | 本机面板进程在上报，不等于浏览器在线，也不证明模型正在执行 |
| 连接器在线 | 该成员、该项目的 SciencePAL worker 最近有心跳 |
| 尚未启动连接器 | 本人在算力网点击启动，队长不能替其他电脑启动 |
| 心跳超时 / 已停止 | 30 秒无心跳，或已明确停止；检查本人入口终端和网络后从同一入口重启 |
| 等待输入 NEEDS_INPUT | 本人在 SciencePAL 原线程回答，连接器核对后接回；不要重新创建远端任务 |
| 未知启动 UNKNOWN | 核对原运行和本机日志，使用已有 recover 流程；不自动盲重发 |
| 评审退回 | 队长确认修改项并安排返工，文件暂不向下游放行 |
| 本轮已完成 | 所有任务获独立评审通过；继续核对科研结论和证据，而非等待连接器 |

在线只说明收到心跳；网络断开不等于远端任务失败。关闭本机终端会停止自己管理的连接器，不保证取消已经发到 SciencePAL 的远端任务。保留日志，恢复时核对原任务。默认个人状态在 `%LOCALAPPDATA%\VibeGit\team-research`，禁止放进项目或发送给其他成员。

加入超时会保留待确认标记，防止重复注册；请队长核对成员身份后处理，不能通过反复点击绕过。已有身份不会被新邀请覆盖。用于另一个房间时选择另一个项目外的个人目录。

## 已验证什么

- 140 项科研回归：会话、来源校验、成员权限、项目绑定、密钥不回传、重复启动、心跳过期、旧实例消息隔离等。另用真实 Node 子进程验证 IPC 安全停止、释放日志锁及再次启动（无远端模型调用）。
- 26 项首次使用浏览器检查（包含原 14 项）：提案各入口回填、草稿保留、并发修改保护、错误邀请可恢复、无效 Key 不保存、无可用 Agent 提示、明确下一步、建项前甘特空状态，以及空白队友加入、本人绑定与提案、双人冻结、发布、未启动提示、启动心跳、退回、停止、阻塞提示、重启后复评与交接、原版抽屉/甘特、390px 无横向溢出。
- 上述浏览器演练使用真实本机面板、Host 权限、任务与连接器逻辑，但 **SciencePAL/Codex 输出为合成结果**，没有使用真实第二账号。真实跨电脑、两账号联调仍需两位本人完成。

可在构建后运行 `node apps/host/scripts/preview-research-onboarding.mjs`，打开输出的演练地址；模拟 Key 填 DEMO-KEY，不能在模拟页输入真实 Key。真实环境不包含合成模型自动执行器。


本轮还将源码包解压到不含 node_modules/dist 的临时目录，通过 open-research.cmd --prepare 完成 npm ci 与全量构建，验证了新安装的本机页面、首次未配置状态及一次性入口。该检查使用当前已安装 Node.js 的 Windows 环境，不代表另一台电脑或真实第二账号已验收。详细观察见 [首次使用复核](SCIENCEPAL-FIRST-USE-REVIEW.md)。

脚本选项：`node scripts/open-research.mjs --prepare` 只准备依赖和构建；`--rebuild` 强制重新构建；`--no-open` 保留终端链接而不自动打开系统浏览器。修改依赖版本后仍先运行 npm ci。

网页与环境脚本现在使用相同的成员/Host/项目日志解析规则，兼容有效的旧日志；发现两份未完成日志时会停下让本人核对，不自动换日志或重发。CLI 的 reply/recover 仍需先停止本人连接器，并在相同 ProfileDir 下配置 -ProjectId。最新混合流程复核见 [同项目协作复核](SCIENCEPAL-MIXED-FLOW-REVIEW.md)。
