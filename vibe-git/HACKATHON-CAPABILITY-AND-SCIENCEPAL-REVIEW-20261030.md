# 能力增量与 SciencePAL 必要性审阅

审阅日期：2026-10-30。范围：产品价值、实现边界、真实科研证据与下一轮优先级。本次只读核查代码和已有产物，并复查官网；没有新调用远端模型、没有重新运行全部测试，也没有部署或提交参赛材料。

## 决策

值得继续，但应把主叙事改成：**让科研团队各自的 Agent，依据同一研究协议，交付可追溯、经过独立复核的科研成果。**

已有工程增量明确；SciencePAL 已进入真实执行，专业环境的价值有证据；“比 Codex 更聪明”“必须使用 SciencePAL 才能做科研”“已经完成真人双账号协作”均未证实。下一轮最值得增加的是能力匹配与科学证据，而非更多平台、按钮或动画。

官方关注科学价值、创新性、可行性，要求 SciencePAL 进入至少一个核心环节；未要求证明其它平台永远无法替代。以 SciencePAL 为主要创作平台，应在研究执行与可验证成果中体现其分量。截止 10 月 31 日 23:59（香港时间）。来源：https://sciencepal.ai/hackathon 。

存在两项当前取舍，不能宣称全面超越原版：

- 原版文档的 task start 可以调用 Codex App Server/CLI；当前科研版的 Codex 页面路径仍是准备任务包、复制任务说明、本人执行后交回。SciencePAL 可由连接器自动领取，Codex 尚不是同等自动执行。
- 当前科研版 `apply-change` 归档旧轮、清空当前任务、重新对齐；且通常需等待当前运行结束才能提变更。它防止旧成果冒充新版，但没有实现原版所描述的细粒度影响处理。不能宣传“只重算受影响实验”已经完成。

## 关键发现（按决策影响排序）

### P1：Iris 的确验证了流程，但无法单独证明选 SciencePAL 的理由

Iris 的 CSV 核验、分组统计和代码检查都可由普通 Python 完成。第一次退回是明示受控错误；第二次缺少可复现代码是自然远端交付缺陷。它证明错误能被发现并阻断交接，不能由此推导某平台的科研智能优势。

建议：Iris 留作易理解的可靠性样例。路演主案例使用已经有真实证据的 1CRN Biology 复算，并在原拓扑显示实际工具、冻结参数、代码、日志与独立结果。无需为体现专业性临时改做药物发现或训练大模型。

### P1：当前“独立评审通过”对证据强度的表达仍不够细

检查 `SPReviewResult` 与 `reviewResult`：现在裁决为 approve / request_changes，逐条检查是布尔值加证据文字，要求引用成果文件名。它能验证结构与一致性，不能仅凭文字证明真的执行了复算，也没有一等的 INCONCLUSIVE。旧专家独立案例已真实出现 INCONCLUSIVE，说明科研复核存在第三种合法结论。

最小改进：每条验收项附证据类型（人工判读、工具日志、独立重算）、证据文件 ID/哈希与检查运行 ID；显示通过/失败/证据不足。缺工具不能被迫写通过或伪装科学失败。对模板内数值指标用已审阅的本地检查器复算；不要为了验证而自动执行任意 Agent 附带代码。

验收：缺失代码、缺失工具、数值超差、只声称运行但无检查产物分别进入正确状态；历史评审如缺此字段显示“历史文字证据”，不伪造追溯认证。

### P1：选专家尚未等同于按能力分派

目录已保留 source/runtimeAgentType/toolProfile，但通用任务契约没有已验证工具能力、探测时刻及所需工具的标准字段。评审者主要按不同 Agent 身份分配，非依据复核所需能力。

最小改进：给成员 Agent 增加可展开的能力记录，标明“目录声明 / 实际探测 / 历史成功”，记录工具版本、观察时刻、来源 Run 和小样本成功证据。任务声明 requiredCapabilities，如 PDB 解析、SASA 计算；匹配真实能力，不硬编码必须某个厂商名。不可用显示未验证或缺工具，交给成员改派或补证。探测结果会过时，不能永久标成当前保证。

验收：Biology 的成功记录可点开；同名通用 Agent 或只有目录标签的 Agent 不被当作已验证；Codex 若也具备并验证了同一能力，允许使用。这样展示 SciencePAL 的真实供应优势，不制造人为锁定。

### P2：两个工作流身份尚不是两个真人协作，收益也未量化

当前真实案例是一位用户控制两个身份。模拟走通与权限负向检查能支持工程实现，不能验证第二账号权限、跨电脑网络与第一次使用成本。156 项回归与 79 项 Iris 核验都不能替代用户测试，也不是科学准确率。

做法：一位真实队友从 ZIP 与说明独立接入；只给任务目标，不由开发者代点全程。记录卡点、人工干预、失败重试和最终交接。此前请继续明确标注“跨平台已实测，真人双账号待验收”。

## SciencePAL 必要性：当前可以说到哪一层

1. **事实：实质使用已经成立。** 原生 Biology 在云端执行结构计算，返回可追溯代码、日志与数值；不是只帮助写简介。1CRN 混合项目有真实线程、输入与下游回执，最终完成。
2. **事实：专业环境有可见贡献。** 独立专家案例实际使用 BioPython 1.84 与 PyMOL 3.2.0a，未临时安装依赖；通用评审环境没有 BioPython/PyMOL。这说明不同 Agent 环境有实质差异，不是名字区别。混合案例只确认 BioPython 数值链；不要把另一次专家运行的 PyMOL 图伪装成混合项目同一条运行。
3. **事实：数值可独立复核。** 已存 `scientific-verification.json` 给出 Biology SASA 2970.152447462 Å²、Codex NumPy 基线 2973.162770614 Å²，相差约 0.10125%。这是同一近似算法家族的两份实现与不同采样分辨率，不是两种完全独立理论，也不是实验真值；一致性不构成新生物学发现。
4. **合理推断：选型有工程理由。** 在不要求每位队友自行搭建专业环境的场景，SciencePAL 提供已经可用的领域执行端，Vibe-Git 提供跨成员的交付与审阅约束。减少配置负担是可检验的预期，尚未量化节省多少时间。
5. **未证明：绝对不可替代或模型更强。** 给 Codex 相同工具与充分配置也可能完成。不得禁止基线安装工具来人为制造胜负。若配置完工具的单 Agent 同样顺手且质量相同，应收窄到协作与环境准备价值。

## 最有说服力的公平验证

拆开两个问题，不能用一个对照同时证明全部价值。

**验证专业环境价值：** 固定 1CRN 输入、方法、验收与交付物，对比 Codex 合理配置工具后单独完成、SciencePAL 原生 Biology 单独完成。分别记录首次环境准备与环境已就绪后的执行；允许正常工具和技能。未知费用填未知，不估造 token 或成本。

**验证协作层价值：** 固定相同 Codex + Biology 执行端，对比人工传文件和本项目工作流。两边都给完整目标、允许人工核对，不故意削弱对照。测试已知、明示的错误：单位错、旧版本替换、遗漏代码、参数变化；同时放入无错对照以测误报。至少展示一个真实自然缺陷（已有 Iris 缺代码即可）。

指标：是否错误放行、是否错误阻断、成果能否复算、人工传递/核对次数、首次配置时间、总历时、返工额外运行、每次失败原因。3–5 个预先登记的小案例可作探索性演示，不报告显著性或普遍提升比例。条件顺序轮换、保存全部运行；控制人工介入，记录操作者经验。相同模型/同一算法会使错误相关，不能只因平台不同就声称统计独立。

**可证伪条件：** 若相同工具的 Codex 完成一样稳定，SciencePAL 价值主要是准备好的环境；若人工传递同样少步骤，团队编排收益不足；若本系统因字段字符串规则反复阻断正确结果，应优先降低协议摩擦，而不是增加 Agent。

## 实施决策与截止前顺序

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| P0-1 | 原界面增加可选择的 1CRN 专业模板与简明专业证据面板 | 新建研究时就能选择；历史回放点任务即可看到实际工具、输入参数、输出代码/日志、独立核验与限制。PyMOL 若来自独立案例须单独标注 |
| P0-2 | 把已有复算证据结构化展示，并加入证据不足状态 | 通过/失败/未验证清楚分开；历史不补造；缺代码或缺检查不得显示已复现。小范围改契约与状态即可，不重写架构 |
| P0-3 | 完成一位真实队友接入和一组人工交接对照 | 保存全过程卡点与交接证据，无法完成则明确剩余边界；不包装模拟为真人测试 |
| P0-4 | 整理可访问作品链接、3–5 分钟视频和不超过 5 页说明 | 外部访问实测；展示 SciencePAL 真实线程/专业产物、原版增量、失败记录。已有原作者为队员，仍区分赛前已有与新增贡献 |
| 后续 | 能力探测与匹配自动化、按参数依赖选择性重算、Codex 自动执行入口 | 公平支持所有已验证平台；重算只影响依赖项且保存复用依据；沿原任务包权限，不绕过成员控制 |

不建议在本轮继续加 DSH、泛化“全学科”、新主页、复杂动画、自动改写任意科研代码、或追求新药/材料发现。剩余时间优先把已有专业证据变成可理解、可复现、可访问的作品。上述工作量是范围决策，不是已完成承诺；若截止前证据不足，保持完整已验证版本，材料明确标注缺口。
