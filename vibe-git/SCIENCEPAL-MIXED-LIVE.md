验证时间：2026-10-30（北京时间）。项目 `947b8993-eb36-4267-99ef-90bf34f5a5e4` 最终状态 **COMPLETED，2 / 2 项通过独立评审**。

## 实际科研任务与结果

数据为 [RCSB PDB 1CRN](https://www.rcsb.org/structure/1CRN) 的公开蛋白质结构，原始文件 49,491 字节，SHA256：

`42199a30a0701864a2a5cc76cd7f35cc544cd0e65fbcf63e03c166543249b811`

研究问题：在固定结构、单位与算法参数下，两端独立实现能否复现几何量及溶剂可及表面积？这是一项描述性复算与流程验证，不是新的生物学发现。

Codex 从实际 PDB 坐标计算：327 个重原子、46 个残基，三条 SG–SG 距离为 2.004107283、2.034701698、2.050763029 Å。

SciencePAL 返回本次实际 Python 源码、BioPython 1.84 / Python 3.12.3 工具日志及全部 46 个残基的表面积。使用 PDBParser 与 [ShrakeRupley](https://biopython.org/docs/1.84/api/Bio.PDB.SASA.html)，960 球面点，1.4 Å 探针，C/N/O/S 半径分别为 1.70/1.55/1.52/1.80 Å。Codex 阅读返回源码并用独立 NumPy 实现重新计算，没有运行 Agent 返回的代码作为自己的独立基线。

| 检查 | 结果 |
|---|---|
| SciencePAL 总 SASA | 2970.152447462 Å² |
| Codex 独立 5000 点基线 | 2973.162770614 Å² |
| 总面积相对差异 | 0.101249860%，小于预先冻结的 3% |
| 六个 CYS 整残基面积 | 全部满足 max(3 Å², 参考值 5%)；最大实际差异约 0.250631 Å² |
| 46 残基面积之和 | 与报告总面积一致 |
| 上游几何文件 SHA256 | `4f3ded1a0ecc5831045e029bc6a366f2c17605407b2d46ca9e732545e2f44281` |

科研优势的证据限于：原生 Biology Agent 中可用的 BioPython 环境、真实结构计算及可复核产物。本次没有证明 SciencePAL 的模型智力优于 Codex，也没有证明工具无法在其他环境安装。

## 实际闭环（包括失败）

1. **领取与对齐**：Codex 使用本人凭据领取冻结协议任务；队长发布两项有硬依赖的研究任务。
2. **真实数据上的受控故障**：首版 Codex 几何输出故意将距离除以十，仍标记为 Å；明确写入 `faultInjection:true`。这用于检验退回，不是自然发生的模型错误。
3. **真实拒绝**：Biology 独立重算并给出 `request_changes`；下游未获派发。原错误文件、检查项和修改意见保留。
4. **返工与一次格式失败**：Codex 改正单位后，SciencePAL 数值评审认可，但一条 `evidence` 未明确写 `geometry.json`，Host 判为 `INVALID`，没有放行。保留了原始无效评审，未替 Agent 改内容或放宽验证。
5. **修复交互协议后复审通过**：错误提示改为定位 `checks[i].evidence` 和必需文件名；输出与重试提示要求逐条自检。显式重试后，真实评审完整通过。
6. **批准后文件交接**：Biology SASA 任务收到的是获批修正版，实际输入哈希与其完全一致，与首版错误文件不同。
7. **真实等待输入**：Agent 在计算前通过提问工具等待探针半径确认。Host 实际观察到 `NEEDS_INPUT`，远端实际状态 `asked`。这是预定的参数确认测试；本轮由 Codex 按冻结协议代提交 1.4 Å 回复，没有声称队友手动回答。
8. **原线程接续**：回复后保持同一线程，仅新增一个运行；旧运行仍为 `asked`，新运行最终 `completed`。没有重新创建研究线程，也没有重复发起接续。
9. **真实交叉复核与界面提交**：Codex 从最终任务包重新运行 NumPy 基线，四项科学验收全部通过；实际点击原拓扑右侧的“检查并交回成果”，Host 接受最终评审，项目完成。

本次共有 8 个本地工作流运行记录（保留 1 个 INVALID），其中 SciencePAL 有 4 个真实线程、5 次远端运行（含 1 次接续）。全流程约 19 分钟，包含人工检查与格式问题排查；这是一次案例记录，不是性能基准。

## 本轮落地的优化

- 科学评审的格式错误精确定位到字段，并给出所需文件名；不因数值看似正确就绕过完整证据要求。
- Agent 输出前自检每个 evidence；格式重试保留原科学标准和原失败结果，不要求 Agent 改变裁决。
- 拓扑、任务详情、成员任务列表与甘特图统一显示当前运行的“等待本人回答”；接续后恢复执行中，旧运行不会污染当前状态。保留原版布局、颜色体系和按钮路径；没有新建另一套界面。
- 新增可恢复的真实案例脚本、科研复核程序、证据核验与截图程序；凭据、日志状态和数据库在项目外。
- 已更新队友源码包，包含公开样本和复现依赖，排除账号 Key、成员凭据、数据库及本轮运行历史。
