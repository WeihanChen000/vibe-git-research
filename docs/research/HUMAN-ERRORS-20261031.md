## 人会遇到的情况

| 情况 | 实测阻断与恢复 |
|---|---|
| 复制损坏的邀请链接 | 修复前误记“加入结果未知”并锁住重试；现在发送前拒绝，可换正确链接直接重试 |
| 服务端接受加入、客户端丢失回执 | 保留待确认记录，拒绝重复注册；模拟中只有一次加入请求，需要队长核对身份 |
| 空文件、超过 256 KiB、非 UTF-8、不支持的文件类型 | 拒绝建项，不留下半个项目、不调用 Agent；更换合法文件可成功 |
| 缺来源署名、HTTP 来源链接 | 拒绝建项；补全来源许可和 HTTPS 链接可继续 |
| 成果文件尚未生成 | 页面交回按钮禁用；本地接口也拒绝缺文件 |
| 空成果、JSON 未写完、带 Markdown 代码框 | 拒绝提交；原领取和输入保留，修正同一文件后接受 |
| 拿错协议版本、缺回执、错误回执、没有 result | 在本地预检查拒绝；未进入评审或下游，修正可继续 |
| 修改冻结输入、篡改获批产物 | 字节检查阻断，不能用文字批准覆盖；走正式返工/变更 |
| 连点旧确认、重复提交、启动第二个连接器 | 旧快照拒绝；相同领取/提交回执可重放，不重复创建执行 |
| 普通成员做队长操作、撤销身份后上传、提交别人的任务 | 服务端权限拒绝，不能靠绕开页面执行 |
| 等待输入时丢失消息/续接回执 | 核对原线程与运行，已保存回答不重发；不确定启动不盲目重开 |
| 项目暂停时提交、旧任务晚到 | 拒绝暂停期间提交和被替代执行；恢复后继续当前任务 |
| 整体放大数值、总量不变但逐项改错、数字写成字符串/空值 | 已配置独立参考时阻断，不能靠评审同意放行 |
| 数值或容差漏填 | 原表单拒绝空白，不静默当成 0；明确输入 0 可接受 |
| 多次续接后重试使累计次数越限 | 按统一运行预算拒绝，重复点击不能突破上限 |

## 修复一：坏链接不应锁住加入

三种编码 `%`、`%ZZ`、`%E0%A4%A` 均复现 `joining=true`。原因是先保存加入中记录，再在发送请求的 try/catch 中解码链接；本地解码失败被误当成网络结果未知。

现在先解码校验，再保存加入中记录。三种坏链接不留下待确认记录，随后正确链接能加入。额外模拟服务端已接受、客户端丢失回执：这一类仍保留待确认状态并拒绝重复加入。没有通过清空所有错误记录掩盖真正的不确定性。

## 修复二：成果语法错误要告诉人如何恢复

空文件、未结束 JSON 和 Markdown 代码框原先只显示英文解析错误。现在提示保存完整 JSON 对象、不要带代码框或解释文字、等待写入完成后再交回，并明确“无需重新领取，原任务与输入保留”。

测试在同一目录写回正确文件，验证接受且执行身份不变。没有放宽版本、输入回执、数值、评审和权限检查。

## 一键复现

在已安装依赖且执行过 `npm run build` 的 `vibe-git` 目录：

```powershell
npm run test:human-errors
```

该命令按名称选择相关用例，正常跳过其余 129 项。机器可读输出：

```powershell
npm run test:human-errors -- --reporter=json --outputFile=data/human-errors.json
```

原始报告含本机路径，应留在忽略提交的 data 目录；公开结果仅保留用例名称、状态与脱敏快照。故障通过隔离模拟注入，未断开本机网络、干扰远程连接或使用真实账号。

## 不能保证的事情

1. 格式合法但研究对象选错的数据，系统未必知道。字节冻结证明后来没被换掉，不证明最初选对了。
2. 人设错参考值或容差过宽，系统不能自动判断科学上合理与否。求和相符也不能单独发现整体同比例错误。
3. 方法字段相符不证明实际执行了方法；逐条需求关联不等于完整语义理解。仍需独立复核原数据、工具和方法证据。
4. 真实 SciencePAL 长时间中断、异机网络和无人协助的新手使用，本轮未实测。历史真实证据未改写。

后续优先让研究者核对选中的数据、方法和独立参考，并根据真实使用记录精简长表单。不要为让测试全绿自动补数值、清掉未知运行，或绕开队长审批。
