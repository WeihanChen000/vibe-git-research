# 科研防偏移收尾与验证（2026-10-31）

这轮把原 Vibe-Git 的“先冻结要求、按原要求执行、变更必须说明影响、旧证据不能冒用”接入科研流程。通用适配器负责跨平台执行，SciencePAL 负责账号可用的科研工具与产物交付；两者都服从同一份协议。没有更换原版界面布局或交互顺序。

**本轮是受控模拟与代码回归，不是新增真实 SciencePAL / Codex / DSH 运行，也不是完整科研实验复现。** 历史真实联调文件没有改写。此前“原功能保留”核对以 `f3e888f` 为上游基线；此轮是在保留原实现的基础上补科研侧机制，不冒称逐字搬运同学原 ZIP。

## 使用方式没有增加一套流程

继续使用原入口：成员提案 → 对齐 / 队长裁决 → 发布 → 本人 Agent 执行 → 独立评审 → 返工或交接。原界面新建的科研项目自动启用治理版本 1，不需要成员填写需求 ID。

- 原“协议”抽屉显示原文覆盖数量、对应任务和队长裁决。遗漏条目会阻止发布，修复对齐结果后重试。
- 原“应用变更”确认框显示每项任务的影响理由，以及要求的替换或撤销。队长确认后才应用。
- 未受影响且已获批的成果经指纹和原批准复核后可复用，任务抽屉注明来源版本；未完成或被影响的任务仍需执行。
- 评审越权加要求会使该评审无效，可重试评审；不会因此自动让作者重新计算。合法的原标准失败仍可按原入口返工。

旧项目、旧回放保留原协议。旧 API 不传 `governanceVersion` 时仍走兼容路径；程序化创建新治理项目须传 `governanceVersion: 1`。不会把旧记录补标成已经通过新版检查。

## 原机制与科研侧的对应

| 原版机制 | 本轮科研实现 | 确定性检查与限制 |
|---|---|---|
| 冻结成员提案，不遗失原要求 | 非空原文行生成稳定要求 ID；任务关联全部现行要求；Host 追加原文验收项 | 能拦截缺失或未知 ID；不能证明 Agent 真正理解了每句话 |
| 队长裁决后继续对齐 | 保留裁决及所引用原文，重新对齐仍携带已选方案 | 原文不删除；科学含义仍需队长核对 |
| 变更逐任务分析影响 | 每项任务须给出影响/无影响理由及当前指纹，下游依赖必须纳入 | 不完整、过期或遗漏下游的影响证据拒绝应用 |
| 长要求增量更新 | 保留原协议，追加操作者真实变更；替换/撤销须明确引用旧要求并经队长确认 | 不接受 Agent 用完整摘要覆盖原协议 |
| 版本改变使旧证据失效 | 任务方法、边界、验收、负责人、源文件、schema、数值规则共同进入指纹 | 领取、派发、回收与交接都核对冻结任务；旧批准不能直接授予新任务 |
| 尽量只返工受影响内容 | 重新对齐时禁止擅改未受影响任务；跨版本复用已批准成果并验证每段变更链 | 适用于阶段边界；没有移植执行中仅暂停部分任务的全部软件调度机制 |
| 按已发布标准评审 | 每项返工要求须引用失败的原验收项；全通过不得另加要求退回 | 能阻止结构上的越权；把新要求伪装成旧标准解释仍需独立评审和人工判断 |

原软件 CLI、防偏移实现、接口契约、Skill 及默认 Codex 保留。同学的 AgentAdapter / AgentRegistry / AgentExecutor 仍是 Relay 与科研执行的共同基础；原 v0.20 主 CLI 开工路径仍是 Codex 专用。科研数值检查是补充，不能替代这些治理机制。

## 三类反例与恢复结果

| 受控问题 | 实际断言 | 恢复路径 |
|---|---|---|
| 对齐漏掉“报告残基数量” | ALIGN 无效，未派发科研执行；原文仍保留 | 补齐关联，重试对齐、发布、执行、评审、完成 |
| 固定 Shrake–Rupley，却交回 Lee–Richards 方法字段 | 冻结 schema 拦截，未进入评审与下游 | 修正产物，重试执行，通过评审和交接 |
| 原验收全通过却要求无关新实验；或新增验收项；或返工不绑定失败项 | 三种评审均无效，作者执行次数仍为 1 | 只重试评审，修正后完成，原成果不重复计算 |

第二项验证的是方法字段约束，不是检测“文字声称用了正确方法、实际偷偷换算法”。真实方法和结果需要工具日志、独立重算及科学检查支持。

另验证了合法退回返工、队长权限、成员连接器、两轮变更、连续未发布变更、伪造复用来源拒绝、历史回放来源隔离，以及变更后原文完整保留。

## 收尾发现并修复的问题

1. 新评审规则曾作用于旧记录，导致历史“全部检查通过但退回”记录不可读。现在以治理版本隔离，新项目严格检查，旧证据按旧契约读取。
2. 连续两个变更若中间版本未发布，已批准且未受影响的成果曾无法复用。现在逐段核对中间变更与任务指纹，保留真正有效的原批准。
3. 自由文本评审摘要中的可选建议曾进入返工指令。现在返工只带失败原标准及其修改要求；可选建议保留在评审记录，不自动升级为必做事项。
4. 首次发布前变更时，下一轮对齐曾缺少上一份任务草案。现在发送真实旧草案，Agent 才能正确保留未受影响任务。
5. 历史阶段展示不能继承当前治理状态；复用成果须显示原始运行和来源版本，不能伪装为本轮新计算；已复用的下游任务仍按原文件回执显示已交接，避免错误显示“等待领取”。

## 仍然适用的边界

- 变更只允许在可变更阶段且没有未收尾运行时提出；不是运行中随时只暂停某一支。原软件这项功能没有被删除，但科研侧不能声称完全等价。
- 原文覆盖目前最多 64 条现行非空行，每行最多 1500 字符；超限明确报错，不截断。它是覆盖单位，不是自动理解的科学需求。
- 固定源文件、方法 schema 和科学检查在发布后不能通过自然语言变更偷偷放宽；真正改变这类基线须重新建项。
- 来源关联、字段检查和数值容差不能保证科学正确；新治理规则还需后续真实 Agent 实跑验证。
- 本轮没有增加平台、实验案例或新页面。完整 Iris / 1CRN 模拟实验留待这一轮收尾后单独开展，不计入以上结果。
