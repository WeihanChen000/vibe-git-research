## 作为黑客松评委

[官方规则](https://sciencepal.ai/hackathon)关注科学价值、创新性与可行性，并要求 SciencePAL 在核心环节实质性参与。没有公布可据以计算总分的权重，因此不虚构评分。

| 判断 | 修改建议 | 本轮落实 |
|---|---|---|
| 工程完成度有证据，但最新结果淹没在历史文档中 | 第一屏用一个问题、一次恢复、一次复用说明价值 | README 和视频页直接展示最新 1CRN 结果、补证与报告变更，并链接完整证据 |
| 原版本来就有多人协作和防偏移，不能把这些统称新增创新 | 讲清扩展发生在哪里，保留队友贡献 | 首页明确原版基础；新增价值集中在跨平台科研文件、输入与方法约束、独立批准随文件交接 |
| SciencePAL 实际使用充分，但“算法不可替代”没有证据 | 展示实际工具及交付，用实际分工说明选择理由 | 明确 Biology 环境的执行、Codex 独立复核与 SciencePAL 报告评审，不宣称算法独占 |

| 视频画面与最新能力不属于同一轮 | 明示版本，给最新证据入口 | 视频页改为“历史基线”，新增最新证据段；旧图明确标为历史案例，不重写旧录像内容 |

**我的评价：** 已具备值得展示的可信工程原型，竞争力来自“跨 Agent 的可核查交接”，而非支持平台的数量。科学案例属于方法复现，尚无新发现；真正未解决的竞争短板是研究者愿不愿承担配置和多轮评审成本。最新两任务流程用了 11 次 Agent 作业，不能仅凭没有重算上游就断言总体更省钱或更快。

## 作为第一次使用的研究者

| 卡点 | 修改建议 | 本轮落实 |
|---|---|---|
| “三步接入”结束后，不知道队长下一步做什么 | 把接入与第一轮操作分开写清 | 补齐建项、对齐、检查配置、发布、执行和完成入口，并给六行提案填写框架 |
| 发布确认很长，关键参数与操作按钮被原文重复淹没 | 保留关键值可见，完整原文按需展开 | 冻结参数和数值规则仍默认显示；验收标准显示条数、原文覆盖数，完整内容通过原有 details 展开 |
| 变更评审长文挤在最前面，看不出到底重做谁 | 先显示影响范围和成果复用条件 | 受影响任务及未受影响任务先显示，长评审理由折叠；实际变更、原要求替换及最终确认仍保留 |
| 缺证据时容易直接点返工，引起多余计算 | 在提交前解释操作后果 | 返工确认明确会重新执行；仅缺原证据时提示先取消、选择补证。补证框显示字符数与长度上限 |
| 快速指南与另一份操作说明给出不同退回处理 | 统一恢复路径 | START 不再把所有退回都导向重算；修正快速指南中缺失的完整接入链接 |

没有自动替用户判断“仅缺证据”，也没有自动批准。用户仍需阅读真实评审意见，队长仍负责发布、变更与返工决策。

## 原版界面与功能保留

对照了原版 InspectorDrawer、InspectorContent 与现有科研确认组件。仍使用原有拓扑/甘特、顶部入口、详情抽屉、按钮和原生折叠区；不改 CSS、配色、字号、布局骨架，也不增加独立导航。修改的是科研确认区的信息展开方式，不声称科研扩展与原版每个像素一致。

本轮没有更改后端状态机、成员权限、冻结协议、输入/成果指纹或队友适配器。发布前的参数核对、全部验收原文和明确确认均保留；折叠不是删掉验收条件。

## 剩下最值得做的事

先完成已有的[单人交接核查对照](manual-handoff-check/README.md)，记录哪里找不到依据、哪里误点、需要多少次补查。这份对照范围有限，不能回答完整配置收益；后续再记录第一次建项与配置负担。

若主要卡在写验收和找参考值，优先改说明或减少不必要配置，不增加更多 Agent 或案例。视频和 PDF 仍是历史版本；本轮先在播放入口标清版本并提供最新证据，后续要更新镜头时，应围绕同一个完成版本录制。
