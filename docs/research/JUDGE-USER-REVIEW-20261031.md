## 后续落地：等待输入时直达原线程

继续审阅发现：原等待输入入口只打开 SciencePAL 首页，远端项目地址到成果交回时才登记，用户需要自己寻找原对话。现在复用连接器本来就执行的线程/Agent/运行历史查询，在等待输入阶段保存对应地址。没有增加 SciencePAL 查询次数，不发送答复或启动新计算；Host 多接收一份幂等的定位回执。

在原“现在轮到谁”待办中，已取得地址时直接打开本次原线程；尚未取得时明确标为查找入口，并保留原编号供核对。用户看到的是原对话回复与连接器接续步骤，CLI 的 work / reply 操作仍保留在原 CLI 路径中。原拓扑、权限、发布与评审顺序不变。

新增回归覆盖：连接器重启后原任务接续；定位查询暂时失败后恢复且不重发；重复状态不使确认过期；其他成员、旧运行回执、项目替换被拒绝；旧连接器不带新字段仍可交回；定位信息不匹配时不生成错误入口；界面直达和明确回退。

这部分由受控连接器模拟、实际 Host API 和 React 渲染验证，不冒充新一轮真实 SciencePAL 等待输入实验；之前的真实科研记录保持原样。

本次收尾验证：科研专项 286 项、原功能兼容 37 项通过；类型检查、完整构建和公开回放构建通过。最新真实证据仍为 31 份附件、34 条回执，离线核验通过；上述新增恢复测试不计作新增真实运行。


## 后续落地：运行上限前置提示

从普通使用者角度继续检查，发现两个可复现问题：补证待办仅按作业数判断额度，遗漏续接；返工在额度已满时仍能改变任务状态，直到后续派发才失败。前者让人填写后才被拒绝，后者造成无法执行的等待状态。

现在 Host、连接器与 CLI / 界面待办共用作业加续接的计数规则。没有剩余额度时，原待办显示已用次数、保留哪些成果以及由队长查看证据核对未完成项；不再提供无法执行的返工、补证和重试入口。Host 在修改返工状态前也强制检查，不依赖界面保护。已派发任务的交回、原记录、成员权限与拓扑布局保持原样，不自动增加上限。

受控反例覆盖：续接耗尽额度时无错误操作入口；仍有一个名额时保留返工/补证选择；成员不能因此得到队长权限；耗尽时不再提示重试、已有运行仍可见；直接调用无额度返工也被拒绝且项目证据完全不变。本轮没有调用真实模型。

本次验证：科研专项 289 项、兼容专项 37 项、类型检查、完整构建与公开构建通过；31 份真实附件、34 条回执及历史回放离线核验通过。历史真实记录未修改；构建仍有既有的大包体积提示。
