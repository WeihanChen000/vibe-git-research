# 可执行科学检查与接入优化 · 2026-10-31

本次是数值门禁实现、保存的真实成果复核、受控反例和界面演练；没有重新调用远端 SciencePAL 或宣称完成真人双账号实验。平台仍是通用科研协作，1CRN 只是带参考配置的示例。

## 行为变化

以前成果格式正确且文字评审同意时，数值错误可能被放行。现在已配置任务必须先通过 Host 的 numeric-v1 检查，Agent 的 approve 不能覆盖失败。提交成果、接受批准、派发下游和阶段完成都会核验；导出证据时也从冻结文件重算。

通用规则支持逐项求和、独立参考数值、按唯一键匹配独立参考表。仅执行宿主内置的有界数值运算，不执行成果、提案或配置中的代码。拒绝缺字段、字符串数值、非有限数、重复/缺失参考键和无效容差。参考比较必须绑定源文件，并注明依据；不证明人为提供的参考本身一定正确。

队长从原“协议”抽屉配置检查。只能首次发布前追加；已有规则不能覆盖，发布后不能删除或放宽。规则另存不可变文件，检查报告绑定规则 SHA256、源文件 SHA256、成果 SHA256 与引擎版本。规则摘要展示在原协议中，失败原因前置到原任务抽屉。

1CRN 可选模板自动带上：原子与残基计数、二硫键配对和距离、总量独立参考、逐残基求和、46 个唯一残基的逐项独立参考。独立参考来自 NumPy 5000 点不同相位实现，本次重新运行总量为 2973.1627706139175 Å²，与已保存参考一致。逐残基容差 max(3 Å², 参考值×5%)，总量相对容差 3%；容差是数值验收约定，不是置信区间。

旧项目和未配置检查的任务继续兼容，明确显示“尚无可执行检查记录”，不追认历史执行已经过新门禁。此功能不保证所有科学错误都能识别，也不以文件哈希证明实际工具执行。

## 验证结果

[机器可读报告](evidence/scientific-gates.json)直接读取未改动的 SciencePAL 原始输出。

| 样本 | 结果 |
|---|---|
| 保存的真实 1000 点成果 | 5 项数值检查通过 |
| 总量单独增加 30 Å² | 求和检查拒绝 |
| 总量和所有残基面积同时放大 20% | 求和仍成立，但独立参考检查拒绝 |
| 两个残基分别加减 20 Å²，总量不变 | 逐项参考检查拒绝 |

后三项明确是受控错误，不是新远端 Agent 自然犯错。报告是局部数值验证，不将其混称为原版完整 UI 或真人效率实验。

集成回归另验证：总是批准的模拟评审不能让坏成果进入评审；伪造缓存报告不能绕过批准阶段重验；人为标记 APPROVED 也不能绕过下游派发检查；失败文件保留，修正后重试完整完成；普通成员不能改队长检查规则，发布后修改被拒绝。

## 接入与界面

新增 `open-captain.cmd`：一个入口启动本机 Host 与队长面板；`open-research.cmd` 给成员使用。跨电脑仍由队长显式准备可信 HTTPS 邀请，不自动开公网或停止占用端口的服务。真实子进程测试覆盖成功启动和端口占用。

算力网显示“加入房间 → 绑定 Agent → 保存提案”三步，首次绑定后进入提案。原人员拓扑、按钮位置、队长权限与待办操作方式保持；科学检查继续使用原协议和任务抽屉。通过浏览器实际保存求和规则，并观察错误成果的阻断状态。

## 重现

在 `vibe-git` 目录构建后运行：

```powershell
node scripts/verify-scientific-gates.mjs
node --test scripts/research-captain.test.mjs
```

`verify-scientific-gates` 不调用模型、不执行附件内代码；默认写入本机 data/scientific-gates。独立重算可运行既有 fixtures/expert-case/reference.py，需要 NumPy。三成员 UI 为隔离合成演练。
