**结论：本轮真实协作完成，17 项运行检查通过。** 一个操作者在同一台电脑上使用现有 Codex 登录和一个 SciencePAL 账号，建立一个队长、两个成员身份。真实科研计算、评审和文件交接均由实际 Agent 完成。没有请三位真人配合，也没有完成跨电脑或不同 SciencePAL 账号验证。

本轮中途发现交接证据不足，由操作者查看原 SciencePAL 对话并补证。因此它证明可恢复的闭环已经完成，**不代表全程无人介入的一键真实成功**。默认一键验收复核公开记录与合成故障场景，不消耗模型额度；`--live` 才启动或继续真实账号运行。

## 分工与科学结果

| 身份 | 平台 | 实际工作 |
|---|---|---|
| 队长 Captain | Codex | 对齐、发布；独立复算和评审，不承担作者任务 |
| 成员 A / Member-B65B | Codex | 领取获批成果，独立求和与校验哈希，写汇总 |
| 成员 B / Member-4BA0 | SciencePAL 官方 Biology Agent | 运行 Bio.PDB Shrake-Rupley，交回参数、代码、逐残基结果和执行输出 |

样例使用公开 1CRN 固定坐标，链 A，327 个重原子、46 个残基，探针半径 1.4 Å。各任务复用冻结源文件，没有重新下载另一个版本。

- 100 点先导：2975.651128 Å²。按约定不足以最终验收，真实评审退回。
- 5000 点成果：2970.926660612643 Å²。
- 队长独立 NumPy 基线：2970.9266606126434 Å²，逐残基最大绝对差约 2.84 × 10⁻¹⁴ Å²。
- 1000/5000 点相对差：0.1114%，低于冻结的 2% 标准。
- 最终科学成果 SHA256：`57217210b2e6be2bd915f65315792c3466c7ac5a22b5f149be98d16330252ede`。

这是计算几何和采样收敛检查，不能推出蛋白生物功能、临床效果或结构变异范围。

## 实际经过与发现的问题

1. 三个身份独立绑定平台；队长冻结源文件、结果格式和可执行数值规则。
2. SciencePAL 首次提交取得真实远端回执后，连接器进程被测试程序主动退出。新进程从原日志接回同一线程/运行，没有重发任务。没有断开电脑网络。
3. SciencePAL 按预设提问，Host 实际观察到 NEEDS_INPUT；预授权测试答复续接原线程，然后执行 100 点先导。
4. 首次评审退回先导精度不足；第二次已完成高精度计算，但缺执行与续接证据；第三次工具输出补齐，仍缺首次提问到计算的顺序。
5. 修复任务包：后续评审和返工可以读取本任务各次执行、续接 ID 与回复哈希。原始回答文本和凭据不进入任务包。
6. 操作者在原 SciencePAL UI 核对提问工具第 5 步与实际计算第 8 步，连同 Host 等待/续接记录形成有来源的有限补证。
7. 新增“补充证据复审”：队长交补证给原独立评审者；不改原文件，不新增第四次计算，不放宽验收标准。补审实际通过后，成员 A 才开始汇总。
8. 汇总和最终评审均通过。对已冻结的 Codex 真实输出主动丢弃一次 HTTP 接收回执，再从原任务目录重传，成果 ID、哈希和项目状态不变。

三次计算、四次 SASA 评审、一次汇总及其评审，加一次对齐，共 **10 次实际 Agent 作业**；其中 SciencePAL 3 次新线程提交、另有 1 次原线程续接。公开回放包含 **13 个真实阶段、23 个原始附件、29 条输入回执**。

## 这轮验收覆盖什么

| 检查 | 结果与边界 |
|---|---|
| 成员身份与权限 | 三个独立项目成员 ID；六项真实 HTTP 403 拒绝，拒绝后项目内容不变 |
| 文件交接 | 下游只收到第三版获批文件，未收到先导版；按原始字节、SHA256 与批准记录匹配 |
| 返工 | 三次退回均保留；独立评审通过前下游没有执行 |
| 中断恢复 | 实际连接器进程退出后恢复原远端任务；没有模拟断网或测试服务端长期离线 |
| 等待输入 | 真实 asked/NEEDS_INPUT、原线程回答与续接；测试答复是预授权固定内容 |
| Codex 回执丢失 | 对已接收真实成果做受控重传；没有重复启动模型 |
| 科学检查 | 对真实 JSON 执行残基总和与数量规则；独立评审另行复算，不以“通过”文字代替检查 |
| 补证复审 | 限队长、同一成果最多一次、仍使用原评审者；原数值门禁与三次执行上限保留 |

## SciencePAL 的作用与证据限制

本例由 SciencePAL 官方 Biology Agent 在其科研环境运行 Bio.PDB，而本地 Codex 环境没有 Bio.PDB，改用独立 NumPy 实现复核。接入利用了真实专家环境、文件沙箱、远端任务和原线程续接；它不是仅在界面中贴一个平台名称。

这证明跨平台专业工具分工有实际用途，**不证明该算法只能由 SciencePAL 完成**。Host 续接回执、操作者查看 UI 的记录、作者报告的工具输出、独立数值复算是不同强度的证据，回放保留各自来源，不把它们写成平台签名的完整审计日志。

本机身份/目录隔离不等于操作系统沙箱；同一 OS 用户仍拥有这些文件。真实两位用户、不同账号权限边界、跨设备网络条件和团队使用体验仍需后续验证。这个案例也没有对人工交接的耗时做公平对照，不能据此宣传节省百分比。平台是通用科研协作，1CRN 只是可复核的演示数据。
